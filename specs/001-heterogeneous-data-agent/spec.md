## User Scenarios & Testing *(mandatory)*

### User Story 1 - 批量异构文档自动处理（Priority: P1）

数据处理操作员将一批格式混杂的文档（PDF / CSV / TXT）放入受监听的文件夹或手动上传，系统自动完成格式判定、路由、解析、质检、修复，输出结构化结果（JSON / CSV / Markdown）与处理报告，全程无需人工逐文件操作。

**Why this priority**: 这是产品的核心价值——"用最划算的算力把 80% 常规数据做对"。没有自动处理链路，其余所有能力都没有承载主体；它是 P0 必须交付的最小可用产品。

**Independent Test**: 放入 100 份混合格式文档（含文本型 PDF、扫描型 PDF、CSV、TXT），任务完成后核对：每份文档均有输出结果与质量标记，报告给出成功数、失败数、成本与耗时，无任何文件被静默丢弃。

**Acceptance Scenarios**:

1. **Given** 文件夹中存在 100 份异构文档（PDF / CSV / TXT，含文本型与扫描型 PDF），**When** 操作员创建处理任务并执行，**Then** 所有文档均被处理：输出对应格式的结构化结果、逐文档质量标记与一份任务总报告，无文件被静默丢弃。
2. **Given** 同一份文档被重复提交，**When** 第二次处理任务执行，**Then** 系统识别重复内容并复用已有结果，不重复解析、不重复计费。
3. **Given** 一份损坏 / 加密 / 截断的文件，**When** 任务执行，**Then** 该文件在任何解析能力被调用之前被拦截，进入带诊断信息的待确认队列，任务其余文件不受影响。
4. **Given** 一份文件后缀名与实际格式不符（如 CSV 改名 `.pdf`），**When** 任务执行，**Then** 按内容而非后缀正确判定格式并进入正确处理链路，同时记录一条后缀不符事件。
5. **Given** 一个任务在批处理中途被强杀，**When** 重启后任务自动恢复，**Then** 已完成的批不重做、从断点继续，最终结果与未中断运行一致。

### User Story 2 - 复杂页识别、标记与人工协同（Priority: P1）

对于无法自动处理好的复杂页面（扫描件、跨页表格断裂、编码损坏等），系统准确识别并清晰标记，附诊断卡说明失败原因、位置与已尝试动作，通过待办清单（P0 以 API / 清单文件形式）交给人工或高成本增强链路处理；最终交付物按缺口页占比分为三档，明确告知哪些内容不可用，而不是假装全部成功。

**Why this priority**: "边界清晰"是区别于"假装成功"产品的核心差异化。复杂页 100% 识别并标记是产品承诺，人工协同与分级交付是这一承诺的落地形态。

**Independent Test**: 构造含复杂页（跨页表格、编码损坏、扫描页）的文档集，验证：所有复杂页被标记、诊断卡包含失败原因与位置、交付物保留占位并标注缺口、报告明确说明降级路径。

**Acceptance Scenarios**:

1. **Given** 一份含跨页表格断裂的 200 页文档，**When** 任务完成，**Then** 失败页被标记为缺口，诊断卡包含原因、位置（页码 + 区域）与建议动作，交付物保留缺口占位、不导致页码错乱。
2. **Given** 一组文档缺口页占比分别约为 0%、3%、8%，**When** 各自任务完成，**Then** 交付等级分别为"完整 / 部分带缺口 / 需人工复核"，其中"需人工复核"强制进入人工队列。
3. **Given** 未配置外部 OCR 增强器的环境，**When** 遇到扫描件或编码损坏页，**Then** 系统按配置降级（默认仅标记不处理），报告显式声明降级路径，被标记内容标注"不可用于自动化下游"。
4. **Given** 同一页存在无法修复的缺陷，**When** 增强回路尝试修复，**Then** 同一缺陷只尝试修复一次，无进展立即停机并升级人工，不无限重试、不原地打转。

### User Story 3 - 业务规则配置（Priority: P2）

业务配置人员用声明式规则包定义字段提取、校验与页级筛选规则（如"只处理带表格的页""营业收入必填""资产负债表勾稽"），无需写代码；规则变更 5 分钟内生效、可版本化、可回滚、可 dry-run 验证。P0 阶段通过 YAML + 校验器 / API 承载，图形化配置界面归 P2。

**Why this priority**: "通用与个性分离"——业务个性化通过配置实现、不侵入核心，是产品解决"个性化需求改动难"的手段。它支撑财报处理、多格式归集、合规审核等场景的落地，属于 P0 之后的增强。

**Independent Test**: 新增一条规则包并在 3 篇样本上 dry-run，确认结果与 diff 后启用；核对新任务按新规则校验、历史任务不受影响、任意历史版本可回滚。

**Acceptance Scenarios**:

1. **Given** 已有基础规则包，**When** 配置人员新增一条勾稽校验并发布，**Then** 新任务按新规则校验，规则在 5 分钟内生效，无需重启服务。
2. **Given** 一条新规则与已有规则冲突，**When** 尝试发布，**Then** 发布被阻断并给出冲突提示。
3. **Given** 规则包新版本运行中发现问题，**When** 配置人员回滚到上一版本，**Then** 历史版本立即生效、操作可审计。
4. **Given** 用户以自然语言描述需求（如"这批年报只处理带表格的页，目录页跳过"），**When** 系统编译为页级筛选规则并经 schema 校验、dry-run、人工确认，**Then** 规则生效；编译失败可回灌重试（最多 2 次）。

### User Story 4 - 质量与成本可度量（Priority: P2）

业务负责人通过报告看到处理质量、成本、异常分布的可信指标：STP 率（一次通过率）、误放率、平均单页成本、兜底档位分布、失败原因分布；任取一个任务可追溯完整决策链。报告分层呈现：任务总览一页、按原因聚合几行、文件清单一列、单文件详情按需生成。

**Why this priority**: "质量不可证明"是行业痛点，可度量的质量与成本是产品对业务负责人的核心卖点，也是内部标定的依据。它建立在 P0 的评测与审计基建之上。

**Independent Test**: 跑完一个 1000 份文件的任务后，核对：总报告为一份小型报告且含核心数字、按原因聚合不超过 10 行、明细仅含"有缺口（gap）的文件"、任取一个文件可还原完整决策链（含兜底档位与修复动作）。

**Acceptance Scenarios**:

1. **Given** 一个 1000 份文件的批处理任务，**When** 任务完成，**Then** 得到一份小型总报告（核心数字一页）+ 一份可筛选的明细清单；默认不生成十万行级页级明细。
2. **Given** 任意一个已处理任务，**When** 业务负责人要求追溯，**Then** 能还原从接入到输出的完整决策链（格式判定、路由理由、解析参数、质量指标、兜底档位、修复动作）。
3. **Given** 处理过程中出现"插件原因未知"的页面，**When** 该比例超过 5%，**Then** 触发告警提示插件升级或映射过期，且上游原始原因被原样保留在报告中。
4. **Given** 产品上线运行一段时间，**When** 每月抽样人工复核，**Then** 质量指标漂移被检测并告警。

### User Story 5 - 部署、运维与扩展（Priority: P3）

系统管理员通过 CLI 一条命令拉起服务，环境自检、状态查询、日志查看、插件管理开箱可用；任务可 7×24 运行，节点故障任务自动转移；离线私有化部署数据不出域；未来单机到多机迁移只改配置不改代码。

**Why this priority**: 部署与运维是规模化交付的前提，但属于 P0 交付后的持续运营能力。离线私有化部署是政企客户的硬需求，P0 阶段以容器化交付 + CLI 骨架先行。

**Independent Test**: 全新机器上一条命令完成部署与环境自检；强杀 worker 后任务从断点继续；断网环境下全链路跑通。

**Acceptance Scenarios**:

1. **Given** 一台全新机器（容器环境可用），**When** 执行一条部署命令，**Then** 服务自动拉起并完成资源自检、依赖校验、插件注册，输出本地访问地址。
2. **Given** 部署环境存在端口占用、磁盘不足、模型缺失之一，**When** 运行环境自检命令，**Then** 能检出问题并给出明确修复建议。
3. **Given** 单机部署的批处理任务，**When** worker 进程被强杀，**Then** 任务从最后完成的批继续，已完成批不重做。
4. **Given** 断网环境且模型 / 字体已预置，**When** 执行含 OCR 路径的任务，**Then** 全链路可运行，数据不出域。

---

### Edge Cases

- 空文件、超大文件、损坏 / 截断 / 加密文件：在处理前拦截，不拖垮任务、不静默丢弃。
- 恶意构造文件（超深页树、超大单页、超高压缩比流）：系统拒收或安全降采样，进程不崩溃。
- 文件后缀与内容不符：按内容判定，记录事件，不误判、不猜。
- 无法判定的格式：归入待确认队列并告警，不得静默丢弃。
- 扫描件但带隐藏 OCR 文本层：先探测文本层并评估质量；可用则复用并标记来源（不送 OCR），不可用才转 OCR；不得把有可用文本层的页直接送入 OCR。
- 同一文件重复提交：内容去重，复用已有结果。
- 单页失败不影响整篇：标记缺口，其余页面正常交付。
- 未知插件原因：原样保留透传，归入兜底缺陷码，计数并告警。
- 超长文档（1000 页以上）：按批处理，文件打开次数不随页数线性增长。
- 外部增强器不可用：按配置降级（仅标记），报告显式声明。
- 增强回路无进展：立即停机，不无限循环、不换花样重试。
- 任务中断（进程崩溃 / 单批异常 / 整体停机）：分别处理，已完成的批不重做。
- 同一缺陷码在同一页重复出现：只修一次，修不动直接升级，不原地打转。
- 执行计划在第 3 次重规划后仍无法达标：停止重规划，交付带缺口的最终结果并在报告中标注。
- 执行计划的分支条件引用了未知或不存在的统计指标：在计划生成期即拒绝，不允许进入执行。

## Requirements *(mandatory)*

### Functional Requirements

**接入与边界处理**

- **FR-001**: 系统 MUST 支持四种数据接入方式——文件夹监听、手动上传、API 推送、数据库定时拉取（P0 交付前两种，P1 交付后两种）；数据库接入必须强制只读、表白名单、参数化模板、单次行数上限、敏感字段自动掩码、每次查询留审计。
- **FR-002**: 系统 MUST 在任何解析能力被调用之前完成文件级体检（空/超大文件、魔数、完整性、交叉引用、页树、页树深度、单页尺寸、对象总数、资源嵌套深度、流压缩比、加密共 11 项），输出三态（正常 / 可修复 / 拒绝）；页树深度超限必须硬拒，可疑项降采样后继续并标记为高风险页。
- **FR-003**: 系统 MUST 按内容而非后缀完成一级格式判定（纯规则、不依赖任何解析插件），输出 pdf / tabular / text / image / unknown 五类家族；判定三态（确信 / 歧义 / 无法分类）——歧义时不得直接猜、须小样本双跑比较质量与成本后再决策，无法分类时进待确认队列并告警；单文件判定开销 ≤ 50ms 且最多读取前 256KB。
- **FR-004**: 系统 MUST 提供两级路由：一级为边界与格式判定，二级仅在 PDF 家族内调用 PDF 分类能力做页级路由；每条路由决策带理由与决策时的画像快照并落库，可事后解释；非 PDF 格式不得经过 PDF 分类能力。

**解析与页面画像**

- **FR-005**: 系统 MUST 以插件形式提供解析能力（P0：PDF、CSV、TXT），新增格式 = 新增插件、核心处理代码零改动；PDF 插件须同时提供分类与抽取两类能力，分别被路由与解析消费。
- **FR-006**: 系统 MUST 对同一文档执行批量化抽取（同一文档的所有页按批一次传入、批内不拆），文件打开与页树解析开销不随页数线性增长；同一文档的所有批落在同一处理单元；扫描页单独成批，不与普通页混批。
- **FR-007**: 系统 MUST 为每页建立页面画像并分两次写入：路由阶段写分类与版式（类型、置信度、路由建议与机器可读原因、栏数、表格、复杂度、旋转），解析完成后写信号与质量（字符密度、字形覆盖、空白占比、页眉页脚占比、抽取质量分、兜底档位）；上游返回的路由原因必须原样保留，不得裁剪、映射或丢弃。
- **FR-008**: 系统 MUST 对复杂页提供分级兜底四档（原样采用 / 后处理修正 / 参数重跑 / 换引擎），档位判定为确定性规则且可复现（同一输入两次判定结果一致）；预算按档扣减（后处理 0 次、参数重跑 1 次、换引擎 2 次），后处理与参数重跑不重新执行解析。

**质量管控与修复**

- **FR-009**: 系统 MUST 提供四层质检：逐页确定性指标（全量、硬门控、定位到页）、昂贵校验（分层抽样 + 低质量页全查）、文档级聚合校验（业务勾稽）、人工例外；逐页校验在任何性能档位下都必须全量执行，禁止"跳过简单页"。
- **FR-010**: 系统 MUST 对未通过质检的页面输出缺陷清单（缺陷码为封闭集、每条必须带可操作位置），质检结果先落库再触发下游；质检只读，不重新解析、不修改产物。
- **FR-011**: 系统 MUST 提供修复能力：基于已有产物做定点修改（后处理优先、不重跑解析），或改变输入 / 参数 / 引擎重跑；同一缺陷码在同一页只尝试修复一次；修复无变化或无量化进展（指标提升 < 5%）立即停机；采纳候选必须带来可量化指标提升，且不得修改原产物。
- **FR-012**: 系统 MUST 将散落失败页聚合成包（50–100 页一包）送外部增强器批量处理，页码映射落盘并参与幂等；只抽取失败页，不重跑整个文件。
- **FR-013**: 系统 MUST 在外部增强器不可用时按配置降级（默认仅标记不处理，其次本地 OCR，"整份不出"仅在客户明确要求时采用），并在报告中显式声明所用降级路径。

**规则与个性化**

- **FR-014**: 系统 MUST 以声明式规则包提供业务规则管理（字段校验、逻辑勾稽、页级筛选），规则为纯数据、可版本化、可回滚、可 dry-run 预览、可静态分析；新增规则 ≤ 5 分钟生效、无需重启；规则引擎为受限表达式，禁止嵌入任意代码。
- **FR-015**: 系统 MUST 提供个性化字段提取的三级降级（声明式锚点提取 / 模板按坐标提取 / 模型兜底），能用规则就不用模型；模型提取结果必须过同一套 schema 校验、单独标记来源并统计占比。
- **FR-016**: 系统 MUST 支持自然语言 → 规则 / 页级筛选的编译链路：草案生成 → schema 校验 → dry-run 报告 → 人工确认 → 冻结生效；编译失败可回灌重试（≤ 2 次），每条规则可追溯到原始需求文本。

**合并、交付与输出**

- **FR-017**: 系统 MUST 合并页级产物（按页码重排、跨页表合并、标题层级重建）并做文档级校验；跨页表合并依据相邻页表头列名相似度与列一致性。
- **FR-018**: 系统 MUST 提供分级交付（完整 / 部分带缺口 / 需人工复核），缺口页必须保留占位、不得跳过，缺口标记内嵌在产物中；输出格式为 JSON / CSV / Excel / Markdown / 数据库写入 + 处理报告。
- **FR-019**: 系统 MUST 提供分层报告（任务总览 / 按原因聚合 / 文件清单 / 按需明细），默认只输出"有缺口的文件"明细，不预生成巨型页级明细文档。

**可靠性与部署**

- **FR-020**: 系统 MUST 保证长任务可续跑：任务状态、画像、报告、缺陷与动作记录持久化，页产物持久化，批级事务边界，先写内容再写索引，恢复从最后完成的批继续、已完成批 0 重做；处理单元无状态。
- **FR-021**: 系统 MUST 在启动时做资源预检并给出建议配置（处理单元数、批大小、内存上限、临时盘预留），用户覆盖后必须做可行性校验、超限告警并降级；运行中对批次做内存估算，超限自动降批（32→16→8），降到最低仍失败则停止并告警，不无限重试。
- **FR-022**: 系统 MUST 对三类后端存储提供可替换性抽象：对象存储至少支持本地与远端两种实现、切换不改变业务行为；队列仅依赖最少语义（不依赖延迟消息与优先级队列）；关系库遵循标准 SQL 子集；文档与页产物以内容哈希标识，更换存储底座不失效。
- **FR-023**: 系统 MUST 提供插件注册表：能力索引、启用 / 禁用、版本锁定、依赖与兼容性校验、同名能力多实现的显式优先级选择；禁止"后加载覆盖先加载"、禁止插件之间直接互调；高频内置插件同进程直接调用，低频 / 第三方插件以隔离方式运行。
- **FR-024**: 系统 MUST 以 CLI 为唯一入口（一条命令拉起服务，Web 状态页由 CLI 拉起、同属一个进程），提供状态 / 日志 / 插件管理 / 环境自检子命令；提供容器化部署（主推）与单机安装两种交付形态；P0 交付 API + CLI + 结果文件 + 处理报告，不依赖任何图形界面。
- **FR-025**: 系统 MUST 提供全链路可观测与审计：每个任务从接入到输出可追溯，所有操作（接入、配置、规则变更、人工修正）留痕；提供处理量、STP 率、误放率、单页成本、档位分布、后处理命中率、时延、复杂页占比等指标；对异常触发告警（STP 跌破阈值、换引擎占比异常上涨、队列积压、节点离线、失败分布漂移）。
- **FR-026**: 系统 MUST 支持任务级执行规划：用户可用自然语言提出处理策略（如"先跑 100 页探路，若一次通过率 ≥ 85% 则全量快速处理，否则降档"），系统编译为受约束的执行计划（仅限处理 / 分支 / 重规划三种环节），预览确认后冻结执行；执行期间如偏离计划可申请重规划（有限次数），超出上限则停止并交付带缺口的结果；任务级模型调用每任务 ≤ 8 次。
- **FR-027**: 系统 MUST 将全部决策点以策略接口形式提供：页级决策（格式路由、兜底档位、修复算子选择、是否续试、何时升级）默认且必须为确定性规则实现，任何情况下不得替换为模型；任务级决策（计划生成、偏离重规划、整本策略切换）可通过同一策略接口由模型实现，且每任务调用次数受限。

### Key Entities *(include if feature involves data)*

- **Task（任务）**: 一次处理请求，含来源、范围（页级筛选）、目标格式、质量要求、预算（成本 / 次数 / 耗时）、性能档位、降级与交付配置；记录续跑点。
- **Document（文档）**: 一个输入文件，以内容哈希标识；含格式家族、页数、页面画像、体检健康状态。
- **PageProfile（页面画像）**: 单页的结构化描述——分类与版式（路由阶段写入）+ 信号与质量（解析完成后写入）。
- **PageArtifact（页产物）**: 单页解析结果（正文、坐标项、表格、阅读顺序、分数、来源），不可变、内容寻址。
- **PageReport（质检报告）**: 单页质检结果——结论、抽取质量分、缺陷清单（缺陷码 + 位置 + 证据 + 严重度 + 建议动作）、归因与置信度。
- **Defect（缺陷）**: 可定位的质量缺陷，驱动修复的唯一入口；必须携带位置，无位置不得入库。
- **PageGap（缺口记录）**: 无法自动修复的页面——失败码、已尝试动作、建议档位、降级手段；供人工与批量增强使用。
- **DocReport（文档报告）**: 文档级聚合质量与诊断。
- **RulePack（规则包）**: 声明式业务规则集合（字段定义、校验、阈值），纯数据、可版本化。
- **Action（修复动作）**: 一次修复尝试——类型、参数、档位、结果与"是否产生实际变化"标志（停机依据）。
- **PluginRegistration（插件注册）**: 插件元数据——标识、版本、能力清单、确定性、信任级、运行形态、启用状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 常规数据处理吞吐 ≥ 30 万页/日/节点（16C64G），端到端 ≤ 150ms/页（前提：简单页占比 ≥ 80%），连续 1 小时压测取稳定值。
- **SC-002**: 加权单页成本 ≤ 全量 OCR 方案的 10%。
- **SC-003**: STP 率（一次通过文档占比）≥ 80%，误放率 ≤ 2%。
- **SC-004**: 复杂页 100% 被识别并标记（附诊断），即使无法自动修复也绝不静默成功。
- **SC-005**: 数据丢失为 0——任何文件不得被静默丢弃；损坏 / 危险文件被拦截并进入带诊断的待确认队列。
- **SC-006**: 文本还原 CER ≤ 2%（简单页）/ ≤ 5%（中等页）；表格结构 TEDS ≥ 0.80（原生）/ ≥ 0.85（含后处理）；标题层级准确率 ≥ 0.78；关键字段 exact match ≥ 98%。
- **SC-007**: 新增业务规则零代码、≤ 5 分钟生效；任意规则可回滚、可追溯、有冲突阻断。
- **SC-008**: 完全离线私有化可运行（含 OCR 路径，模型预置），数据不出域。
- **SC-009**: 单机 → 多机迁移只改配置不改代码；10 节点吞吐提升 ≥ 70%。
- **SC-010**: 长任务可续跑：强杀处理单元后恢复耗时 ≤ 30s，已完成的批 0 重做。
- **SC-011**: 单进程峰值内存 ≤ 50 MB（批 32 页）；批级文件打开次数不随页数线性增长。
- **SC-012**: 质检器自身 precision ≥ 0.95、recall ≥ 0.90（黄金集评测）；页级抽取质量分与人工"需介入"判定一致率 ≥ 0.85；质量综合分与人工总分 Spearman 相关 > 0.8。
- **SC-013**: 文档级勾稽通过率 ≥ 99%；72 小时压测无内存泄漏（内存占用增长 < 5%）、无无限循环（预算注入全部按预期升级）。
- **SC-014**: 同一执行计划版本（`plan_version`）重放历史任务，输出结果逐字一致；单任务任务级模型调用 ≤ 8 次。

## Assumptions

- **交付范围**：本 spec 以 PRD V2.3 的 P0（MVP）为交付范围——接入（文件夹 + 上传）、文件体检、两级路由、PDF / CSV / TXT 解析、页面画像、分级兜底、后处理修正、四层质检、缺陷与修复、规则包、合并输出、分级交付、续跑、资源预检、存储抽象、插件注册表、CLI / 容器化交付。P1 / P2（数据库与 API 接入、OCR / 图片 / 对照插件、分布式多节点、自然语言编译、可观测看板、PII 掩码、离线安装包、全部图形界面、MCP 出口等）不在 P0 交付范围。
- **界面时点**：P0 / P1 只交付 API + CLI + 结果文件 + 处理报告；对话界面、看板、待办队列图形化、管理台统一归 P2，验收标准不含任何界面项。
- **目标客户与语料**：银行、保险、券商、审计、律所、政府档案与大型企业财务共享中心；目标语料以中文为主（财报、法规、合同）。
- **统计前提**：简单页占比 ≥ 80% 是吞吐与成本目标的统计前提（简单 : 中等 : 复杂 ≈ 8 : 1.5 : 0.5）。
- **解析能力来源**：PDF 分类与抽取能力复用现有 PDF 处理库（pdf-inspector），接口依据为 `doc/pdf-inspector.md`；该能力只提供分类与 Markdown / 坐标抽取，表格 cell 级结构、跨页表续接、页眉页脚剔除等需系统自建后处理补齐。
- **隐藏文本层边界**：pdf-inspector 不暴露扫描件中的不可见文本层（`invisible_text_layer` 页返回空），系统需通过底层 PDFium 探测并按质量门复用；文本层质量不达标时才走 OCR，报告须声明文本来源。该澄清不改变 P0 交付范围，只明确 FR-005 / FR-013 的实现边界。
- **页码基准**：系统内部一律 1-indexed，插件页码基准转换点全工程仅一处、以断言式测试固定（因接口文档中不同接口及同一返回对象内部页码基准不一致）。
- **插件治理**：插件注册表 P0 必做；独立插件网关 P0 不做；MCP 仅作 P2 对外出口、不做内部调用协议。
- **确定性边界**：页级决策（兜底档位判定、门控判定、路由决策、算子选择、是否续试、何时升级，含失败归因）一律确定性规则、不由模型决定；任务级模型调用收敛为「任务级三处」（意图→Plan、偏离重规划、整本策略切换），每任务 ≤ 8 次；模型输出为封闭标签集或受 schema 约束的结构化结果。
- **接入安全**：数据接入默认只读；数据库连接器遵守只读账号、表白名单、参数化模板、行数上限、超时与敏感字段掩码红线。
- **后端依赖**：产品依赖对象存储、队列、关系库三类后端；P0 提供本地内置实现、可替换为独立部署的远端实现，业务行为不变。
