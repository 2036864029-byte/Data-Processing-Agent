# ADR-0004：P0-A 单文件任务拆分口径

- **状态**：Accepted
- **日期**：2026-11-01
- **相关**：P0-A（A1–A9，T001–T072）、`tasks.md`

## 背景

P0-A 是基础支撑层，模块之间层间依赖明确（`apps → pipeline → kernel → platform → contracts`），
且要求 TDD（先红后绿）。若按“大模块”一次性落地，评审与回滚成本高，import-linter 门禁
也难以及时定位越界。

## 决策

- 每个实现任务对应**一个源码文件**（必要时加一个测试文件）；任务粒度以“可独立测试”为准。
- 测试任务先于实现任务，依次跑红 → 绿；每个 Phase 结束跑全量门禁后 commit + push。
- 单个文件承担单一职责；跨文件共享类型上提到 `contracts/`，控制逻辑收敛到 `kernel/`。
- 不以“减少文件数”为目标；宁可多一个小组件，不做巨型模块。

## 后果

- 提交历史按 Phase / 文件可读，import-linter 每次都能指出具体越界文件。
- 部分相关逻辑分散在多个文件（如告警规则与分发同文件、执行设施分 sandbox/pool/heartbeat），
  通过包 `__init__` 与文档建立索引。
- P0-B 功能模块沿用同一拆分口径；跨阶段复用（例如 sandbox 被 A6 复用）显式记录在 ADR。
